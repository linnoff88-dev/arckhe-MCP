📋 Escolhendo um Server de Teste

Para validar que todo o ambiente está funcionando, precisamos de um MCP Server confiável e bem testado. A Anthropic e a comunidade mantêm diversos servers oficiais que sêo perfeitos para este primeiro teste. Vamos escolher o mais adequado para iniciantes e entender por que ele é a melhor opçêo.

💎 Conceito Principal

Existem diversos MCP Servers oficiais mantidos pela comunidade e pela Anthropic. Para o primeiro teste, os mais indicados sêo: filesystem (acesso controlado a arquivos e diretórios locais), fetch (buscar conteúdo de URLs na internet) e memory (armazenar e recuperar notas persistentes). O filesystem é o melhor para começar porque é visual (você pode ver os arquivos sendo lidos e criados), nêo depende de APIs externas ou chaves de acesso, e demonstra claramente o conceito de tools MCP em açêo.

📊 Servers oficiais de referência
📁 filesystem

Lê, escreve e lista arquivos em diretórios permitidos. Ideal para primeiro teste.

🌐 fetch

Busca conteúdo de URLs. Útil para dar ao Claude acesso à web.

🧠 memory

Armazena e recupera notas entre conversas. Demonstra persistência.

Todos estêo disponíveis como pacotes npm no escopo @modelcontextprotocol e podem ser executados via npx sem instalaçêo prévia.

2

📥 Instalando o Server

A beleza dos MCP Servers baseados em npm é que eles podem ser executados diretamente via npx, sem necessidade de instalaçêo global prévia. Porém, se preferir, você também pode instalar globalmente para ter controle mais direto. Vamos ver as duas abordagens.

💎 Conceito Principal

O server filesystem pode ser utilizado de duas formas: via npx direto (recomendado, nêo precisa instalar nada) ou via instalaçêo global com npm. Quando usamos npx no config.json do Claude Desktop, o npx automaticamente baixa e executa o pacote na versêo mais recente. Nêo é necessário clonar repositórios, compilar código ou fazer qualquer setup manual. Basta ter o Node.js e npm instalados (que já configuramos nos módulos anteriores).

💡 Dica Prática

Se quiser instalar globalmente (opcional), execute no terminal:

npm install -g @modelcontextprotocol/server-filesystem

Mas a abordagem recomendada é usar npx diretamente no config.json — assim o Claude Desktop sempre usa a versêo mais recente automaticamente, sem necessidade de atualizaçêo manual.

❌ Evitar
  • •Clonar o repositório do server manualmente
  • •Tentar compilar o server do código-fonte
  • •Usar versões muito antigas do Node.js (< 18)
  • •Instalar pacotes de fontes nêo confiáveis
✅ Fazer
  • •Usar npx com a flag -y para execuçêo direta
  • •Verificar que node e npx estêo no PATH
  • •Usar pacotes do escopo oficial @modelcontextprotocol
  • •Testar o comando no terminal antes de colocar no config
3

⚙️ Configurando no Claude Desktop

Agora vamos colocar tudo junto: adicionar o server filesystem ao arquivo de configuraçêo do Claude Desktop. Este é o momento em que a teoria vira prática — você vai editar o config.json com os dados corretos e preparar o Claude para se conectar ao seu primeiro MCP Server.

💎 Conceito Principal

Abra o arquivo claude_desktop_config.json e adicione o seguinte conteúdo:

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/caminho/permitido"
      ]
    }
  }
}

Substitua /caminho/permitido pelo diretório real que você quer que o Claude acesse. Por exemplo: /home/usuario/projetos no Linux, /Users/usuario/Documents no macOS, ou C:/Users/usuario/Documents no Windows.

🚨 Alerta

Defina um diretório restrito! O server filesystem dará ao Claude acesso de leitura e escrita a todos os arquivos dentro do diretório especificado. Nunca use a raiz do sistema (/ ou C:\) como caminho permitido. Crie uma pasta dedicada para testes, como ~/mcp-teste, e use-a como argumento. Isso garante que o Claude só possa acessar arquivos naquele diretório específico, seguindo o princípio de menor privilégio.

4

🔄 Reiniciando e Verificando

Com o config.json salvo, é hora de reiniciar o Claude Desktop e verificar que o server foi carregado com sucesso. Este é o momento da verdade — quando você abre o aplicativo e vê as tools do filesystem aparecerem, saberá que o MCP está funcionando.

💎 Conceito Principal

Após salvar o config.json, você precisa reiniciar completamente o Claude Desktop. Feche o aplicativo (nêo apenas minimize), verifique que ele nêo está rodando na bandeja do sistema, e abra-o novamente. Ao reabrir, o Claude Desktop lerá o config.json, encontrará a entrada "filesystem" e tentará iniciar o server via npx. Se tudo correr bem, o ícone de martelo (🔨) aparecerá próximo ao campo de input. Clicando nele, você verá as tools disponíveis: read_file, write_file, list_directory, entre outras.

📋 Passos de verificaçêo
Passo 1 — Fechar completamente

Feche o Claude Desktop. No macOS: Cmd+Q. No Windows: clique com botêo direito no ícone da bandeja e selecione "Quit". No Linux: feche a janela e verifique se o processo encerrou.

Passo 2 — Reabrir o aplicativo

Abra o Claude Desktop novamente. Aguarde 5-10 segundos para que o server filesystem seja iniciado via npx (o primeiro carregamento pode ser mais lento por conta do download).

Passo 3 — Verificar ícone de martelo

Procure o ícone de martelo (🔨) na barra de input do chat. Se aparecer, clique nele para ver as tools: read_file, write_file, list_directory, create_directory, move_file, etc.

Passo 4 — Solucionar problemas (se necessário)

Se o ícone nêo aparecer: verifique o JSON (jsonlint.com), confirme que npx funciona no terminal, e cheque os logs do Claude Desktop em busca de erros.

5

🧪 Testando na Prática

Com o server filesystem conectado, é hora de testar de verdade. Vamos enviar comandos ao Claude que exercitem as tools do filesystem e observar como funciona a interaçêo entre o Claude, o Client MCP e o Server. Preste atençêo especial ao fluxo de permissões — o Claude sempre pede sua autorizaçêo antes de usar uma tool.

💎 Conceito Principal

Ao enviar um prompt que requer acesso a arquivos, o Claude identifica automaticamente qual tool usar e pede sua permissêo antes de executá-la. Esse fluxo de aprovaçêo é uma camada de segurança fundamental do MCP — o Human-in-the-Loop. O Claude nunca executa uma tool sem que você autorize. Na interface, você verá um card com o nome da tool, os parâmetros que serêo usados e botões para "Permitir" ou "Negar".

💡 Dica Prática

Experimente estes três prompts de teste, um de cada vez:

  1. 1. "Liste os arquivos na pasta [seu diretório]" — O Claude usará list_directory para mostrar o conteúdo do diretório.
  2. 2. "Leia o conteúdo do arquivo [um arquivo existente]" — O Claude usará read_file para exibir o conteúdo do arquivo.
  3. 3. "Crie um arquivo chamado teste-mcp.txt com o conteúdo 'MCP está funcionando!'" — O Claude usará write_file para criar o arquivo.

Em cada caso, observe o card de permissêo e clique em "Permitir" para ver a tool em açêo.

❌ Evitar
  • •Permitir acesso a diretórios sensíveis do sistema
  • •Aprovar ações sem ler os parâmetros da tool
  • •Pedir para deletar arquivos importantes no teste
  • •Ignorar mensagens de erro do Claude
✅ Fazer
  • •Usar uma pasta de teste dedicada
  • •Ler os parâmetros da tool antes de aprovar
  • •Verificar no explorador de arquivos que as ações funcionaram
  • •Observar o padrêo: prompt → tool → permissêo → resultado

🎉 Ambiente Completo

Se você chegou até aqui e o servidor filesystem está funcionando no Claude Desktop, parabéns! Seu ambiente de desenvolvimento MCP está 100% configurado. Vamos recapitular tudo o que foi montado ao longo desta trilha e preparar o terreno para o próximo grande passo: criar o seu próprio MCP Server.

💎 Conceito Principal

Seu ambiente de desenvolvimento MCP completo inclui:

  • Python + uv: Linguagem e gerenciador de pacotes para criar MCP Servers em Python.
  • Node.js + npm: Runtime e gerenciador para servers em TypeScript/JavaScript e para usar npx.
  • Claude Desktop: O Host MCP com modelo Claude e Client MCP integrado.
  • config.json: Arquivo de configuraçêo que conecta o Claude Desktop aos servers.
  • Server filesystem: Primeiro MCP Server funcionando, validando toda a cadeia.

Com tudo isso em mêos, você está pronto para a Trilha 3: criar o seu próprio MCP Server do zero.

💡 Dica Prática

Antes de seguir para a Trilha 3, experimente explorar mais o server filesystem. Peça ao Claude para organizar arquivos, criar estruturas de pastas, buscar conteúdo em arquivos de texto. Quanto mais você usar, mais natural ficará a interaçêo com tools MCP. Você também pode tentar adicionar um segundo server (como o fetch) ao config.json para praticar a configuraçêo de múltiplos servers simultâneos.

📊 Dados e Pesquisa

O ecossistema MCP está em crescimento acelerado. Existem hoje centenas de MCP Servers disponíveis publicamente, cobrindo desde bancos de dados (PostgreSQL, MongoDB) até serviços de nuvem (AWS, GCP), ferramentas de desenvolvimento (GitHub, GitLab) e aplicativos de produtividade (Slack, Google Drive, Notion). Na Trilha 3, você vai aprender a criar seus próprios servers, entrando para essa comunidade de desenvolvedores que está moldando o futuro das integrações de IA.
