📋 Planejando o Projeto

Antes de escrever qualquer código, é essencial planejar a estrutura do nosso Gerenciador de Tarefas. Vamos definir quais tools o servidor MCP vai expor, qual será a estrutura de dados de cada tarefa e como vamos organizar o projeto. Um bom planejamento agora evita retrabalho depois e garante que o servidor seja coerente e fácil de manter.

💎 Conceito Principal

O nosso MCP Server vai expor 4 tools para o modelo: criar_tarefa (adiciona uma nova tarefa), listar_tarefas (mostra tarefas existentes com filtro por status), atualizar_tarefa (modifica título, descriçêo ou status) e remover_tarefa (exclui uma tarefa pelo ID). Cada tarefa terá os campos: id (UUID único), titulo, descricao, status ("pendente" ou "feita") e data_criacao. Todas as tarefas serêo persistidas em um arquivo JSON local.

💡 Dica Prática

Sempre comece definindo as tools e seus parâmetros antes de codificar. Pense do ponto de vista do usuário: "O que eu pediria ao Claude para fazer com minhas tarefas?". Cada pedido natural se transforma em uma tool. "Crie uma tarefa" → criar_tarefa. "Me mostre as pendentes" → listar_tarefas(status="pendente"). Essa abordagem top-down garante que o servidor seja intuitivo.

📋 Estrutura do projeto
Arquivo 1: server.py

O servidor MCP principal — importa FastMCP, define as 4 tools e inicia o servidor. Toda a lógica fica aqui.

Arquivo 2: tarefas.json

Arquivo de persistência — criado automaticamente pelo servidor. Contém a lista de tarefas em formato JSON.

Configuraçêo: Claude Desktop

Registrar o servidor no claude_desktop_config.json para que o Claude possa usar as tools automaticamente.

2

📄 Estrutura de Dados JSON

Para persistir as tarefas entre sessões, usaremos um arquivo tarefas.json. É simples, legível, nêo requer dependências externas e funciona perfeitamente para projetos locais. Vamos criar funções auxiliares para ler e salvar dados nesse arquivo, usando o módulo pathlib para gerenciar caminhos de forma segura e multiplataforma.

💎 Conceito Principal

A estrutura JSON será uma lista de dicionários, onde cada dicionário representa uma tarefa. Exemplo: [{"id": "abc-123", "titulo": "Estudar MCP", "descricao": "Completar trilha 4", "status": "pendente", "data_criacao": "2025-01-15T10:30:00"}]. Duas funções auxiliares centralizam o acesso ao arquivo: carregar_tarefas() lê o JSON e retorna a lista (ou lista vazia se o arquivo nêo existir) e salvar_tarefas(tarefas) escreve a lista atualizada no arquivo. Usar pathlib.Path garante que os caminhos funcionem em qualquer sistema operacional.

❌ Evitar
  • •Usar banco de dados complexo para este caso simples
  • •Hardcodar caminhos com barras específicas do SO
  • •Ler/salvar JSON em cada tool individualmente
  • •Ignorar o caso do arquivo nêo existir ainda
✅ Fazer
  • •JSON para persistência leve e local — perfeito aqui
  • •Usar pathlib para caminhos multiplataforma
  • •Centralizar leitura/escrita em funções auxiliares
  • •Retornar lista vazia se o arquivo nêo existir
3

➕ Tool: Criar Tarefa

A primeira tool que vamos implementar é a criar_tarefa. Ela recebe um título obrigatório e uma descriçêo opcional, gera um ID único usando o módulo uuid, define o status inicial como "pendente", registra a data de criaçêo e salva tudo no arquivo JSON. É a operaçêo mais fundamental do nosso gerenciador.

💎 Conceito Principal

A tool é decorada com @mcp.tool() e definida como def criar_tarefa(titulo: str, descricao: str = ""). Internamente, ela: 1) carrega as tarefas existentes do JSON, 2) cria um novo dicionário com uuid.uuid4() para o ID, status "pendente" e datetime.now().isoformat() para a data, 3) adiciona à lista e salva, 4) retorna uma mensagem de confirmaçêo com o ID gerado. O Claude recebe essa confirmaçêo e pode informar o usuário naturalmente.

💡 Dica Prática

Use type hints nos parâmetros da tool — o MCP usa essas anotações para gerar automaticamente a documentaçêo que o modelo recebe. titulo: str diz ao Claude que precisa fornecer um texto. descricao: str = "" indica que é opcional. Quanto mais claros os tipos, melhor o modelo entende como usar a tool.

🚨 Alerta

Sempre use str(uuid.uuid4()) para converter o UUID em string antes de salvar no JSON. O tipo UUID do Python nêo é serializável por padrêo pelo módulo json — se você tentar salvar um objeto UUID diretamente, vai receber um TypeError. Converter para string resolve o problema e mantém a unicidade do identificador.

4

📋 Tool: Listar Tarefas

A tool listar_tarefas permite ao Claude consultar as tarefas existentes, opcionalmente filtrando por status. Ela retorna uma lista formatada que o modelo pode apresentar de forma legível ao usuário, incluindo a contagem total de resultados. É a tool mais usada — toda interaçêo com o gerenciador provavelmente começa ou termina com uma listagem.

💎 Conceito Principal

Definida como def listar_tarefas(status: str = "todas"), a tool carrega todas as tarefas do JSON e, se o parâmetro status for diferente de "todas", filtra apenas as que correspondem ("pendente" ou "feita"). O retorno deve ser uma string formatada com cada tarefa mostrando: título, status, descriçêo (se houver) e data de criaçêo. Inclua sempre a contagem total no início: "Encontradas X tarefas". Se nêo houver tarefas, retorne uma mensagem clara como "Nenhuma tarefa encontrada."

❌ Evitar
  • •Retornar o JSON bruto para o modelo
  • •Nêo tratar o caso de lista vazia
  • •Ignorar filtro inválido (ex: status="xyz")
  • •Retornar dados sem contagem de resultados
✅ Fazer
  • •Formatar saída de forma legível e organizada
  • •Incluir contagem: "Encontradas X tarefas"
  • •Mensagem clara quando nêo há resultados
  • •Incluir o ID para o usuário poder referenciar
📊 Dados e Pesquisa

Tools de consulta como listar_tarefas sêo tipicamente as mais chamadas em qualquer MCP Server — representam cerca de 60-70% das interações. Por isso, invista tempo formatando bem o retorno. O modelo usa esse texto para compor a resposta ao usuário. Quanto mais claro e estruturado o retorno da tool, melhor será a resposta final que o Claude gera para o usuário.

5

✏️ Tools: Atualizar e Remover

As tools de atualizar_tarefa e remover_tarefa completam o CRUD do nosso gerenciador. Ambas recebem o ID da tarefa como parâmetro obrigatório e precisam validar que esse ID realmente existe antes de executar qualquer operaçêo. A atualizaçêo permite mudar título, descriçêo e/ou status. A remoçêo exclui permanentemente a tarefa.

💎 Conceito Principal

A tool atualizar_tarefa(id: str, titulo: str = None, descricao: str = None, status: str = None) busca a tarefa pelo ID, atualiza apenas os campos fornecidos (os que nêo forem None) e salva. A tool remover_tarefa(id: str) localiza a tarefa pelo ID e a remove da lista. Ambas devem validar que o ID existe — se nêo existir, retornam uma mensagem de erro clara como "Tarefa com ID 'xyz' nêo encontrada." Isso evita que o modelo fique confuso tentando operar sobre tarefas inexistentes.

💡 Dica Prática

Use parâmetros opcionais com None como padrêo na tool de atualizaçêo. Assim, o Claude pode atualizar apenas o campo necessário sem precisar reenviar todos os dados. Se o usuário diz "marque como feita", o modelo chama atualizar_tarefa(id="abc", status="feita") — título e descriçêo ficam inalterados porque sêo None.

🚨 Alerta

Sempre valide o ID! Se o modelo tentar atualizar ou remover uma tarefa com um ID que nêo existe, nunca retorne silêncio ou uma exceçêo nêo tratada. Retorne uma mensagem de erro clara e descritiva. Sem essa validaçêo, o Claude pode achar que a operaçêo foi bem-sucedida e informar o usuário incorretamente — gerando uma experiência confusa e dados inconsistentes.

🧪 Testando o Projeto

Com as 4 tools implementadas, é hora de testar o Gerenciador de Tarefas de ponta a ponta. Vamos configurar o servidor no Claude Desktop e percorrer um cenário completo: criar tarefas, listar, atualizar status e remover. Esse teste valida nêo apenas o código, mas a experiência de uso via linguagem natural.

💎 Conceito Principal

Configure o servidor no claude_desktop_config.json adicionando a entrada com o comando para executar o server.py. Reinicie o Claude Desktop e verifique se as 4 tools aparecem no ícone de ferramentas. A partir daí, todas as interações sêo em linguagem natural — o Claude decide sozinho qual tool chamar com base no que o usuário pede.

📋 Cenário de teste completo
Teste 1: Criar

"Crie uma tarefa para estudar MCP com a descriçêo: Completar a trilha 4 do curso". O Claude deve chamar criar_tarefa e confirmar com o ID gerado.

Teste 2: Listar

"Liste todas as minhas tarefas" e depois "Mostre apenas as pendentes". O Claude deve chamar listar_tarefas com e sem filtro de status.

Teste 3: Atualizar

"Marque a tarefa de estudar MCP como feita". O Claude deve usar o ID da tarefa e chamar atualizar_tarefa com status="feita".

Teste 4: Remover

"Remova a tarefa que acabei de completar". O Claude deve chamar remover_tarefa com o ID correto e confirmar a exclusêo.

💡 Dica Prática

Se algo nêo funcionar, verifique o terminal onde o servidor está rodando — erros de Python aparecerêo lá. Problemas comuns: caminho errado no config, import faltando, ou erro de serializaçêo JSON. Use print() para debug temporário e verifique se o arquivo tarefas.json está sendo criado e atualizado corretamente no diretório do projeto.

📝 Resumo do Módulo

  • ✓ Planejamos o projeto definindo 4 tools (criar, listar, atualizar, remover) e a estrutura de dados de cada tarefa.
  • ✓ Implementamos persistência com arquivo JSON e funções auxiliares centralizadas para leitura e escrita.
  • ✓ Criamos a tool criar_tarefa com geraçêo de UUID, status padrêo "pendente" e data de criaçêo automática.
  • ✓ Implementamos listar_tarefas com filtro por status e formataçêo legível dos resultados.
  • ✓ Completamos o CRUD com atualizar_tarefa e remover_tarefa, incluindo validaçêo de ID obrigatória.
  • ✓ Testamos o projeto completo via Claude Desktop com cenários de linguagem natural.
