🐍 Instalando Python y uv

Configura Python 3.11+ y el administrador de paquetes uv para el desarrollo con MCP.

Qué es:

Python es un lenguaje de programación de alto nivel, conocido por su sintaxis sencilla y legibilidad. Es el lenguaje principal para desarrollar MCP Servers gracias al SDK oficial de Anthropic y a la amplia biblioteca de integraciones disponibles.

Por qué aprender:

El SDK oficial de MCP para Python es el más maduro y documentado. La mayoría de los ejemplos y tutoriales usan Python, por lo que es la opción más práctica para empezar.

Conceptos clave:

Python 3.11+, lenguaje interpretado, tipado dinámico, ecosistema de paquetes, SDK de MCP para Python.

Qué es:

Python 3.11+ se puede instalar descargando el instalador oficial de python.org o usando administradores de versiones como pyenv. Se necesita la versión 3.11 o superior para que sea compatible con el SDK MCP y sus funciones de tipado moderno.

Por qué aprender:

Sin Python instalado correctamente, ningún MCP Server en Python funcionará. Una instalación limpia evita problemas de permisos y conflictos de versiones en el futuro.

Conceptos clave:

python.org, pyenv, PATH del sistema, versión mínima 3.11, instalador por sistema operativo.

Qué es:

uv es un gestor de paquetes y entornos virtuales de Python ultrarrápido, escrito en Rust. Reemplaza pip, venv y pip-tools con una sola herramienta que resuelve e instala dependencias entre 10 y 100 veces más rápido.

Por qué aprender:

uv es la herramienta recomendada por el ecosistema MCP para gestionar proyectos Python. Su velocidad y simplicidad hacen que el desarrollo sea mucho más productivo.

Conceptos clave:

uv, Astral, Rust, resolución de dependencias, entornos virtuales, sustitución de pip.

Qué es:

uv se puede instalar mediante curl (en Linux/Mac) o pip (en cualquier sistema). Se recomienda el comando curl porque instala directamente el binario compilado, sin depender de una instalación previa de Python.

Por qué aprender:

uv debe estar instalado y disponible en el PATH antes de crear cualquier proyecto MCP. Una instalación correcta evita problemas de permisos y conflictos.

Conceptos clave:

curl, pip install uv, binario independiente, PATH, permisos de instalación.

Qué es:

Después de instalar Python y uv, es esencial verificar que ambos estén accesibles desde la terminal. Los comandos python --version, python3 --version y uv --version confirman que las herramientas están en el PATH y funcionan correctamente.

Por qué aprender:

Comprobar la instalación de inmediato previene frustraciones futuras. Muchos errores en tutoriales de MCP ocurren porque Python o uv no están configurados correctamente.

Conceptos clave:

python --version, uv --version, PATH, variables de entorno, solución de problemas de instalación.

Qué es:

La primera prueba práctica consiste en usar uv para crear un entorno virtual aislado, instalar un paquete de prueba y ejecutar un script sencillo. Esto valida que toda la cadena Python + uv funciona correctamente en tu sistema.

Por qué aprender:

Crear un entorno virtual es el primer paso de cualquier proyecto MCP en Python. Practicarlo ahora te asegura que sabrás hacerlo automáticamente cuando empieces a construir servers.

Conceptos clave:

uv venv, uv pip install, entorno virtual, aislamiento de dependencias, activación del venv.

📦 Instalando Node.js y npm

Configuración alternativa para quienes prefieren TypeScript durante el desarrollo de MCP Servers.

Qué es:

Node.js es un runtime que permite ejecutar JavaScript fuera del navegador. Basado en el motor V8 de Chrome, permite crear aplicaciones server-side, incluidos MCP Servers con TypeScript y el SDK oficial.

Por qué aprender:

Node.js es la segunda opción oficial para desarrollar MCP Servers. Si ya conoces JavaScript o TypeScript, puede ser la forma más rápida de empezar a crear servers.

Conceptos clave:

Node.js, runtime de JavaScript, V8, server-side, TypeScript, event loop, non-blocking I/O.

Qué es:

Node.js se puede instalar mediante nvm (Node Version Manager), que permite administrar varias versiones, o con el instalador oficial de nodejs.org. Se recomienda nvm para desarrolladores que trabajan en distintos proyectos.

Por qué aprender:

Una instalación correcta de Node.js evita problemas de permisos y conflictos de versiones. nvm facilita cambiar de versión según sea necesario para diferentes proyectos.

Conceptos clave:

nvm, nodejs.org, LTS vs Current, instalación por sistema operativo, administración de versiones.

Qué es:

npm (Node Package Manager) es el gestor de paquetes predeterminado de Node.js. Permite instalar, actualizar y gestionar bibliotecas JavaScript/TypeScript, incluido el SDK MCP para TypeScript y todas sus dependencias.

Por qué aprender:

Todo proyecto de Node.js usa npm para administrar dependencias. Entender cómo funciona es esencial para instalar el SDK de MCP y mantener tus proyectos organizados.

Conceptos clave:

npm, package.json, node_modules, npm install, npm init, registro de paquetes, semver.

Qué es:

npx es una herramienta que viene con npm y permite ejecutar paquetes de Node.js sin instalarlos globalmente. Los descarga, ejecuta y elimina automáticamente. Se usa mucho para ejecutar MCP Servers de prueba y herramientas de scaffolding.

Por qué aprender:

npx se usa con frecuencia para ejecutar MCP Servers directamente, sin necesidad de instalarlos de forma permanente. Es la manera más rápida de probar servers de terceros.

Conceptos clave:

npx, ejecución temporal, sin instalación global, caché de paquetes, npm vs npx.

Qué es:

Comprobar la instalación con node -v, npm -v y npx --version confirma que todas las herramientas están accesibles en la terminal. Las versiones deben ser compatibles: se recomienda Node.js 18+ para el SDK MCP TypeScript.

Por qué aprender:

Validar cada herramienta individualmente garantiza que no haya problemas de PATH o de versión. Una lista de verificación rápida ahorra horas de debugging después.

Conceptos clave:

node -v, npm -v, npx --version, versión mínima, compatibilidad, lista de verificación de validación.

Qué es:

La primera prueba práctica consiste en ejecutar un paquete sencillo con npx para validar que Node.js y npm funcionan correctamente. Esto simula el flujo que se usará más adelante para ejecutar MCP Servers de TypeScript.

Por qué aprender:

Probar la cadena completa Node.js + npm + npx con un ejemplo real garantiza que tu entorno esté listo para desarrollar MCP Servers en TypeScript.

Conceptos clave:

npx create-*, ejecución de paquetes, flujo de pruebas, validación del entorno, solución de problemas.

💻 Conociendo la terminal

Comandos esenciales de la terminal para quienes nunca han usado la línea de comandos.

Qué es:

La terminal (o línea de comandos) es una interfaz basada en texto que permite interactuar con la computadora escribiendo comandos. A diferencia de la interfaz gráfica, la terminal ofrece un control preciso y automatizable del sistema operativo.

Por qué aprender:

Todo el desarrollo de MCP se hace en la terminal, desde instalar dependencias hasta ejecutar servers y configurar Claude Desktop. Dominar la terminal es un requisito fundamental.

Conceptos clave:

Terminal, shell, bash, zsh, PowerShell, símbolo del sistema, interfaz CLI.

Qué es:

Los comandos de navegación permiten moverte entre directorios en la terminal. cd (change directory) cambia de carpeta, ls (list) muestra el contenido de un directorio y pwd (print working directory) muestra dónde estás actualmente.

Por qué aprender:

Navegar por el sistema de archivos es la habilidad más básica y más usada en la terminal. Necesitarás acceder a carpetas de proyectos, encontrar archivos de configuración y organizar tus MCP Servers.

Conceptos clave:

cd, ls, pwd, rutas absolutas frente a relativas, directorio de inicio (~), directorio padre (..).

Qué es:

Los comandos para manipular archivos permiten crear (touch, mkdir), copiar (cp), mover/renombrar (mv) y eliminar (rm) archivos y directorios directamente desde la terminal, sin necesitar una interfaz gráfica.

Por qué aprender:

Gestionar archivos desde el terminal es más rápido y preciso que hacerlo desde la interfaz gráfica. Crearás carpetas de proyecto, copiarás templates y organizarás tus MCP Servers constantemente.

Conceptos clave:

touch, mkdir, cp, mv, rm, rm -r, flags, confirmación de eliminación, permisos.

Qué es:

Editar archivos desde la terminal se puede hacer con editores como nano (simple, dentro de la terminal), code (abre VS Code) o visualizar el contenido con cat. Cada herramienta tiene su caso de uso ideal.

Por qué aprender:

Tendrás que editar directamente archivos de configuración como claude_desktop_config.json. Saber usar al menos un editor de terminal es esencial para configurar MCP Servers.

Conceptos clave:

nano, vim, code (VS Code), cat, less, more, redirección de salida (>, >>).

Qué es:

Los comandos de búsqueda como find (localiza archivos por nombre o tipo) y grep (busca texto dentro de archivos) son grandes aliados. El pipe (|) permite encadenar comandos y enviar la salida de uno como entrada del siguiente.

Por qué aprender:

Buscar archivos de configuración, encontrar errores en logs y filtrar resultados son tareas habituales en el desarrollo de MCP. Estos comandos ahorran mucho tiempo.

Conceptos clave:

find, grep, pipe (|), expresiones regulares, filtros, encadenamiento de comandos.

Qué es:

Los atajos de teclado hacen que usar la terminal sea mucho más eficiente. Tab completa automáticamente comandos y rutas, las flechas recorren el historial, Ctrl+C cancela procesos y Ctrl+R busca comandos anteriores.

Por qué aprender:

Los atajos transforman la terminal de una herramienta intimidante en una experiencia fluida. Ctrl+C en particular es esencial para detener MCP Servers durante el desarrollo.

Conceptos clave:

Autocompletado con Tab, flechas arriba/abajo, Ctrl+C, Ctrl+D, Ctrl+R, Ctrl+L, historial de comandos.

🖥️ Instalando Claude Desktop

Configuración paso a paso de Claude Desktop en Windows, Mac y Linux.

Qué es:

Claude Desktop es la aplicación oficial de Anthropic que permite interactuar con Claude directamente en tu computadora. Funciona como un MCP Host y puede conectarse a MCP Servers locales y remotos para ampliar las capacidades de Claude.

Por qué aprender:

Claude Desktop es el principal MCP Host para desarrollo y pruebas. Allí conectarás tus MCP Servers y verás cómo funcionan las tools en la práctica.

Conceptos clave:

Claude Desktop, MCP Host, aplicación nativa, Anthropic, interfaz de chat, soporte para MCP.

Qué es:

La descarga de Claude Desktop se realiza desde el sitio oficial de Anthropic (claude.ai/download). La instalación varía según el sistema: en Windows es un instalador .exe, en Mac un .dmg y en Linux un .deb o .AppImage, según la distribución.

Por qué aprender:

Sin Claude Desktop instalado, no podrás probar tus MCP Servers de forma visual e interactiva. Es el entorno principal de desarrollo y validación.

Conceptos clave:

claude.ai/download, instalador por sistema operativo, permisos de instalación, requisitos del sistema, actualizaciones.

Qué es:

La configuración inicial de Claude Desktop implica iniciar sesión con tu cuenta de Anthropic, aceptar los términos de uso y ajustar las preferencias básicas. Después de iniciar sesión, la aplicación está lista para usar Claude, pero aún no tiene MCP Servers conectados.

Por qué aprender:

Una configuración inicial correcta garantiza que la aplicación funcione sin problemas. Los errores en esta etapa pueden impedir la conexión con MCP Servers más adelante.

Conceptos clave:

Cuenta de Anthropic, inicio de sesión, términos de uso, preferencias, plan de suscripción, límites de uso.

Qué es:

Los MCP Servers se registran en el archivo claude_desktop_config.json, ubicado en rutas específicas según el sistema: ~/Library/Application Support/Claude/ en Mac, %APPDATA%/Claude/ en Windows y ~/.config/Claude/ en Linux.

Por qué aprender:

Saber dónde está el archivo de configuración es esencial para agregar, editar y depurar MCP Servers. Es el archivo que editarás con más frecuencia durante el desarrollo.

Conceptos clave:

claude_desktop_config.json, rutas por SO, directorio de configuración, Application Support, AppData.

Qué es:

La lista de validación incluye: la aplicación se abre sin errores, el inicio de sesión funciona, es posible enviar mensajes a Claude, se puede acceder al menú de configuración y el archivo de configuración existe en la ruta correcta del sistema.

Por qué aprender:

Validar cada punto de la lista de verificación previene problemas cuando empieces a conectar MCP Servers. Un entorno saludable es la base para un desarrollo productivo.

Conceptos clave:

Lista de verificación, validación, solución de problemas, logs de errores, reinicio, soporte técnico.

Qué es:

El primer uso consiste en iniciar una conversación con Claude en Desktop, probar distintos tipos de preguntas y explorar la interfaz. Esto confirma que la aplicación funciona y te familiariza con el entorno donde probarás tus MCP Servers.

Por qué aprender:

Conocer la interfaz de Claude Desktop antes de agregar MCP Servers te permite identificar rápidamente los cambios cuando se conecten los servers, como la aparición de nuevas tools en la interfaz.

Conceptos clave:

Interfaz de chat, nueva conversación, modelos disponibles, límites de uso, experiencia de referencia.

⚙️ Configuración de claude_desktop_config.json

Entiende la estructura del archivo de configuración y cómo registrar MCP Servers.

Qué es:

claude_desktop_config.json es el archivo de configuración central de Claude Desktop para MCP. Contiene la lista de todos los MCP Servers registrados, sus comandos de ejecución, argumentos y variables de entorno necesarias.

Por qué aprender:

Este archivo es el puente entre Claude Desktop y tus MCP Servers. Si no está configurado correctamente, la aplicación no detectará ni ejecutará ningún server.

Conceptos clave:

claude_desktop_config.json, configuración declarativa, registro de servers, JSON, mcpServers.

Qué es:

El archivo de configuración está en distintas ubicaciones según el sistema: ~/Library/Application Support/Claude/claude_desktop_config.json en Mac, %APPDATA%\Claude\claude_desktop_config.json en Windows y ~/.config/Claude/claude_desktop_config.json en Linux.

Por qué aprender:

Encontrar el archivo rápidamente es esencial para la productividad. Editarás este archivo con frecuencia durante el desarrollo y la depuración de MCP Servers.

Conceptos clave:

Rutas por sistema operativo, Application Support, AppData, .config, directorio oculto, acceso mediante terminal.

Qué es:

La estructura de config.json tiene un objeto raíz con la clave "mcpServers", que contiene un objeto donde cada clave es el nombre de un server y el valor define command (obligatorio), args (opcional) y env (opcional para variables de entorno).

Por qué aprender:

Entender la estructura del JSON evita errores de sintaxis y garantiza que tus servers se registren correctamente. Un campo incorrecto puede impedir que el server se inicie.

Conceptos clave:

mcpServers, command, args, env, estructura JSON, claves obligatorias, formato correcto.

Qué es:

Registrar un server implica agregar una nueva entrada al objeto mcpServers con un nombre identificador, el comando para ejecutarlo (como "python" o "npx"), los argumentos necesarios (como la ruta del script) y variables de entorno opcionales.

Por qué aprender:

Esta es la acción que realizarás cada vez que crees o instales un nuevo MCP Server. Dominar el registro garantiza que tus servers aparezcan y funcionen correctamente en Claude Desktop.

Conceptos clave:

Registro de server, nombre identificador, command, args, env, reinicio de Claude Desktop.

Qué es:

Los errores más comunes en config.json incluyen: comas faltantes o sobrantes (JSON inválido), rutas absolutas incorrectas, uso de barras invertidas en Windows sin escape, falta de permisos de ejecución y variables de entorno sin definir.

Por qué aprender:

Conocer los errores comunes antes de encontrarlos te ahorra horas de frustración. La mayoría de los problemas con MCP Servers se debe a errores sencillos en el archivo de configuración.

Conceptos clave:

JSON inválido, coma final, rutas absolutas, escape de barras, permisos, depuración.

Qué es:

Validar la configuración implica: verificar el JSON con un linter en línea o una herramienta local, probar las rutas de los comandos en la terminal, reiniciar Claude Desktop y comprobar si los servers aparecen en la lista de tools disponibles.

Por qué aprender:

Un proceso de validación sistemático garantiza que los cambios en el config funcionen antes de empezar a usar el server. Esto crea un ciclo de retroalimentación rápido durante el desarrollo.

Conceptos clave:

Linter de JSON, prueba de rutas, reinicio, lista de tools, logs de Claude Desktop, validación.

🧪 Primera prueba: MCP Server de ejemplo

Clona y ejecuta un servidor de referencia para validar que todo el entorno funcione.

Qué es:

Anthropic y la comunidad mantienen varios MCP Servers oficiales de referencia. Para la primera prueba, se recomienda usar un server sencillo, como el filesystem server o el everything server, que muestran las funcionalidades básicas sin dependencias complejas.

Por qué aprender:

Empezar con un server de referencia comprobado garantiza que cualquier problema se deba a tu entorno y no al código. Es la mejor forma de validar la instalación completa.

Conceptos clave:

Servers de referencia, filesystem server, everything server, repositorios oficiales, complejidad mínima.

Qué es:

Clonar un repositorio significa descargar todo el código fuente de un MCP Server mediante git clone. El comando copia el repositorio de GitHub a una carpeta local de tu computadora, lista para instalar y ejecutar.

Por qué aprender:

La mayoría de los MCP Servers se distribuyen a través de GitHub. Saber clonar repositorios es la forma estándar de obtener e instalar servers de la comunidad.

Conceptos clave:

git clone, GitHub, repositorio, URL del repositorio, directorio de destino, branch predeterminada.

Qué es:

Después de clonar el repositorio, debes instalar las dependencias del server. Para los servers de Python, se usa uv pip install o pip install -r requirements.txt. Para los servers de Node.js, se usa npm install. Esto descarga todas las bibliotecas necesarias.

Por qué aprender:

Instalar correctamente las dependencias es el paso que más errores genera para principiantes. Entender el proceso evita problemas de paquetes faltantes o incompatibles.

Conceptos clave:

pip install, npm install, uv pip install, requirements.txt, package.json, resolución de dependencias.

Qué es:

Configurar el server en Claude Desktop significa agregar una entrada en claude_desktop_config.json con el comando de ejecución, la ruta del script y las variables de entorno necesarias. Después de guardar, hay que reiniciar Claude Desktop.

Por qué aprender:

Este es el momento en que la teoría se convierte en práctica. Configurar un server real en Claude Desktop conecta todos los conceptos aprendidos hasta ahora en una experiencia funcional.

Conceptos clave:

Edición de config.json, entrada del server, comando de ejecución, ruta absoluta, reinicio.

Qué es:

Probar la conexión implica abrir Claude Desktop después de reiniciarlo y verificar si las tools del MCP Server aparecen en la interfaz. Puedes ver los servers conectados y sus tools disponibles en el ícono de herramientas de la interfaz de chat.

Por qué aprender:

Comprobar la conexión confirma que todo el pipeline funciona: config.json correcto, server ejecutable, comunicación MCP establecida. Es el checkpoint final antes de usar el server.

Conceptos clave:

Tools disponibles, ícono de herramientas, lista de servers, estado de conexión, registros de errores.

Qué es:

El primer uso real consiste en pedirle a Claude que use una tool del MCP Server conectado. Por ejemplo, puedes pedirle que liste los archivos de una carpeta (filesystem server) o que ejecute una operación específica. Claude identificará la tool y te pedirá aprobación antes de usarla.

Por qué aprender:

Este es el momento «¡ajá!» del curso: ver a Claude usando una tool que se ejecuta en tu computadora. Esto valida todo el entorno y te motiva a crear tus propios servers.

Conceptos clave:

Invocación de tool, aprobación del usuario, resultado de la tool, flujo completo, depuración, próximos pasos.
