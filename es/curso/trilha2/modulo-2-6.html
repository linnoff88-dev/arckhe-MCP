📋 Cómo elegir un server de prueba

Para validar que todo el entorno funciona, necesitamos un MCP Server confiable y bien probado. Anthropic y la comunidad mantienen varios servers oficiales que son perfectos para esta primera prueba. Vamos a elegir el más adecuado para principiantes y entender por qué es la mejor opción.

💎 Concepto principal

La comunidad y Anthropic mantienen varios MCP Servers oficiales. Para la primera prueba, los más recomendados son: filesystem (acceso controlado a archivos y directorios locales), fetch (buscar contenido de URL en Internet) y memory (almacenar y recuperar notas persistentes). El filesystem es la mejor opción para empezar porque es visual (puedes ver cómo se leen y crean los archivos), no depende de API externas ni de claves de acceso, y demuestra claramente el concepto de tools MCP en acción.

📊 Servers oficiales de referencia
📁 filesystem

Lee, escribe y lista archivos en directorios permitidos. Ideal para una primera prueba.

🌐 fetch

Busca contenido de URLs. Es útil para darle a Claude acceso a la web.

🧠 memory

Almacena y recupera notas entre conversaciones. Demuestra persistencia.

Todos están disponibles como paquetes npm en el ámbito @modelcontextprotocol y se pueden ejecutar con npx sin instalarlos previamente.

2

📥 Cómo instalar el Server

La ventaja de los MCP Servers basados en npm es que pueden ejecutarse directamente con npx, sin necesidad de una instalación global previa. Sin embargo, si lo prefieres, también puedes instalarlos globalmente para tener un control más directo. Veamos ambos enfoques.

💎 Concepto principal

El server filesystem puede utilizarse de dos formas: mediante npx directo (recomendado, no necesitas instalar nada) o mediante instalación global con npm. Cuando usamos npx en el config.json de Claude Desktop, npx descarga y ejecuta automáticamente el paquete en su versión más reciente. No es necesario clonar repositorios, compilar código ni hacer ninguna configuración manual. Basta con tener Node.js y npm instalados (que ya configuramos en los módulos anteriores).

💡 Consejo práctico

Si quieres instalarlo globalmente (opcional), ejecuta en el terminal:

npm install -g @modelcontextprotocol/server-filesystem

Pero la enfoque recomendado es usar npx directamente en config.json: así Claude Desktop siempre usa automáticamente la versión más reciente, sin necesidad de actualizarla manualmente.

❌ Evitar
  • •Clonar manualmente el repositorio del server
  • •Intentar compilar el server desde el código fuente
  • •Usar versiones muy antiguas de Node.js (< 18)
  • •Instalar paquetes de fuentes no confiables
✅ Hacer
  • •Usar npx con la flag -y para la ejecución directa
  • •Comprobar que node y npx estén en el PATH
  • •Usar paquetes del ámbito oficial @modelcontextprotocol
  • •Probar el comando en la terminal antes de ponerlo en el config
3

⚙️ Configuración en Claude Desktop

Ahora pongamos todo junto: agregaremos el server filesystem al archivo de configuración de Claude Desktop. Este es el momento en que la teoría se vuelve práctica: editarás el config.json con los datos correctos y prepararás Claude para conectarse a tu primer MCP Server.

💎 Concepto principal

Abre el archivo claude_desktop_config.json y agrega el siguiente contenido:

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/caminho/permitido"
      ]
    }
  }
}

Reemplaza /caminho/permitido por el directorio real al que quieres que Claude acceda. Por ejemplo: /home/usuario/projetos en Linux, /Users/usuario/Documents en macOS, o C:/Users/usuario/Documents en Windows.

🚨 Alerta

¡Define un directorio restringido! El server filesystem dará a Claude acceso de lectura y escritura a todos los archivos dentro del directorio especificado. Nunca uses la raíz del sistema (/ o C:\) como ruta permitida. Crea una carpeta dedicada a las pruebas, como ~/mcp-teste, y úsala como argumento. Esto garantiza que Claude solo pueda acceder a archivos de ese directorio específico, siguiendo el principio de mínimo privilegio.

4

🔄 Reiniciando y verificando

Con config.json guardado, es hora de reiniciar Claude Desktop y verificar que el server se haya cargado correctamente. Este es el momento de la verdad: cuando abras la aplicación y veas aparecer las tools del filesystem, sabrás que MCP está funcionando.

💎 Concepto principal

Después de guardar el config.json, necesitas reiniciar por completo Claude Desktop. Cierra la aplicación (no basta con minimizarla), verifica que no siga ejecutándose en la bandeja del sistema y vuelve a abrirla. Al abrirse, Claude Desktop leerá el config.json, encontrará la entrada "filesystem" e intentará iniciar el server mediante npx. Si todo sale bien, ícono de martillo (🔨) aparecerá junto al campo de entrada. Al hacer clic en él, verás las tools disponibles: read_file, write_file, list_directory, entre otras.

📋 Pasos de verificación
Paso 1 — Cerrar por completo

Cierra Claude Desktop. En macOS: Cmd+Q. En Windows: haz clic derecho en el ícono de la bandeja y selecciona "Quit". En Linux: cierra la ventana y verifica que el proceso haya terminado.

Paso 2 — Volver a abrir la aplicación

Abre Claude Desktop de nuevo. Espera 5-10 segundos a que se inicie el server filesystem mediante npx (la primera carga puede tardar más debido a la descarga).

Paso 3 — Verificar el ícono de martillo

Busca el ícono de martillo (🔨) en la barra de entrada del chat. Si aparece, haz clic para ver las tools: read_file, write_file, list_directory, create_directory, move_file, etc.

Paso 4 — Solucionar problemas (si es necesario)

Si el ícono no aparece: revisa el JSON (jsonlint.com), confirma que npx funciona en el terminal y busca errores en los logs de Claude Desktop.

5

🧪 Probando en la práctica

Con el server filesystem conectado, es hora de probarlo de verdad. Enviaremos comandos a Claude que pongan a prueba las tools del filesystem y observaremos cómo funciona la interacción entre Claude, el Client MCP y el Server. Presta especial atención al flujo de permisos: Claude siempre pide tu autorización antes de usar una tool.

💎 Concepto principal

Al enviar un prompt que requiere acceso a archivos, Claude identifica automáticamente qué tool usar y te pide permiso antes de ejecutarla. Este flujo de aprobación es una capa de seguridad fundamental de MCP: el Human-in-the-Loop. Claude nunca ejecuta una tool sin que tú la autorices. En la interfaz, verás una tarjeta con el nombre de la tool, los parámetros que se usarán y botones para "Permitir" o "Denegar".

💡 Consejo práctico

Prueba estos tres prompts de prueba, uno a la vez:

  1. 1. "Lista los archivos en la carpeta [tu directorio]" — Claude usará list_directory para mostrar el contenido del directorio.
  2. 2. "Lee el contenido del archivo [un archivo existente]" — Claude usará read_file para mostrar el contenido del archivo.
  3. 3. "Crea un archivo llamado teste-mcp.txt con el contenido '¡MCP está funcionando!'" — Claude usará write_file para crear el archivo.

En cada caso, observa la tarjeta de permiso y haz clic en "Permitir" para ver la tool en acción.

❌ Evitar
  • •Permitir el acceso a directorios sensibles del sistema
  • •Aprobar acciones sin leer los parámetros de la tool
  • •Pedir que se eliminen archivos importantes durante la prueba
  • •Ignorar mensajes de error de Claude
✅ Hacer
  • •Usar una carpeta de prueba dedicada
  • •Leer los parámetros de la tool antes de aprobar
  • •Comprobar en el explorador de archivos que las acciones hayan funcionado
  • •Observa el patrón: prompt → tool → permiso → resultado

🎉 Entorno completo

Si llegaste hasta aquí y el servidor filesystem funciona en Claude Desktop, ¡felicitaciones! Tu entorno de desarrollo MCP está 100% configurado. Recapitulemos todo lo que configuraste a lo largo de esta ruta y preparemos el terreno para el próximo gran paso: crear tu propio MCP Server.

💎 Concepto principal

Tu entorno completo de desarrollo MCP incluye:

  • Python + uv: Lenguaje y gestor de paquetes para crear MCP Servers en Python.
  • Node.js + npm: Runtime y gestor para servers en TypeScript/JavaScript y para usar npx.
  • Claude Desktop: El Host MCP con el modelo Claude y un Client MCP integrado.
  • config.json: Archivo de configuración que conecta Claude Desktop con los servers.
  • Server filesystem: Primer MCP Server en funcionamiento, validando toda la cadena.

Con todo esto en tus manos, estás listo para la Ruta 3: crear tu propio MCP Server desde cero.

💡 Consejo práctico

Antes de seguir con la Ruta 3, prueba explorar más el server filesystem. Pídele a Claude que organice archivos, cree estructuras de carpetas y busque contenido en archivos de texto. Cuanto más lo uses, más natural será la interacción con las tools MCP. También puedes intentar agregar un segundo server (como el fetch) al config.json para practicar la configuración de varios servers simultáneamente.

📊 Datos e investigación

El ecosistema MCP está creciendo rápidamente. Actualmente hay cientos de servidores MCP disponibles públicamente, desde bases de datos (PostgreSQL, MongoDB) hasta servicios en la nube (AWS, GCP), herramientas de desarrollo (GitHub, GitLab) y aplicaciones de productividad (Slack, Google Drive, Notion). En la Trilha 3, aprenderás a crear tus propios servers y a unirte a esta comunidad de desarrolladores que está moldeando el futuro de las integraciones de IA.
