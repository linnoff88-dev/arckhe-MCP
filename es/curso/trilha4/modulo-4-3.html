📁 Planificando las tools

El Asistente de Archivos es un proyecto que combina el poder de MCP con operaciones del sistema de archivos. Vamos a crear 4 herramientas que permiten a Claude interactuar con archivos y carpetas locales: leer contenido, buscar texto, generar estadísticas y organizar archivos automáticamente. Todo usando los módulos pathlib e os de la biblioteca estándar de Python.

💎 Concepto principal

Las 4 tools del Asistente de Archivos: ler_arquivo(caminho) — lee el contenido de un archivo de texto y lo devuelve con metadatos (tamaño, fecha de modificación); buscar_en_arquivos(pasta, texto) — busca una cadena en todos los archivos de una carpeta de forma recursiva y devuelve el archivo, la línea y el contexto; estatisticas_pasta(caminho) — cuenta los archivos por extensión, el tamaño total y los archivos más grandes y más pequeños; organizar_por_tipo(pasta) — mueve archivos a subcarpetas organizadas por extensión (.pdf para PDFs/, .jpg para Imágenes/, etc.). Todas usan pathlib.Path para manipular rutas de forma segura.

💡 Consejo práctico

Usa pathlib.Path en lugar de os.path para todas las operaciones con rutas. pathlib ofrece una API más intuitiva y orientada a objetos: Path("pasta").iterdir() para listar, path.suffix para extensión, path.stat().st_size para el tamaño. Además, funciona correctamente en Windows, Linux y macOS sin ajustes manuales de barras.

2

📖 Tool: leer y resumir

La tool ler_arquivo es la más básica y poderosa de nuestro asistente. Lee el contenido de un archivo de texto y lo devuelve junto con metadatos útiles, como el tamaño y la fecha de modificación. Lo más interesante es que Claude resume naturalmente el contenido al presentárselo al usuario: no necesitas implementar una lógica de resumen, el modelo lo hace por sí solo.

💎 Concepto principal

La tool ler_arquivo(caminho: str) usa Path(caminho) para abrir el archivo, lee el contenido con path.read_text(encoding="utf-8") y recopila metadatos mediante path.stat(): tamaño en bytes/KB, fecha de la última modificación con formato. El resultado combina los metadatos y el contenido en una cadena organizada. Claude recibe todo esto y puede resumirlo, analizarlo o responder preguntas sobre el contenido, sin que tengas que agregar código de IA.

❌ Evitar
  • •Leer archivos binarios (.exe, .zip, imágenes) como texto
  • •Leer archivos enormes (>1MB) completos de una sola vez
  • •No verificar si el archivo existe antes de leerlo
  • •Ignorar errores de codificación (UnicodeDecodeError)
✅ Hacer
  • •Limitar la lectura a extensiones de texto conocidas
  • •Truncar archivos grandes (p. ej., los primeros 10KB)
  • •Comprobar path.exists() y path.is_file() antes
  • •Usar try/except para manejar errores de encoding
🚨 Alerta

¡Limita el tamaño de la lectura! Si el usuario pide leer un archivo de 500MB, el servidor intentará cargarlo todo en la memoria y enviarlo como respuesta de la tool; esto puede bloquear el servidor o superar los límites del modelo. Define un límite seguro (p. ej., 10.000 caracteres) y, si el archivo es más grande, devuelve solo el comienzo con un aviso: "Archivo truncado: se muestran los primeros 10KB de 500MB."

3

🔍 Tool: Buscar en archivos

La tool buscar_en_arquivos funciona como un "grep" inteligente: recibe una carpeta y un texto que buscar, y recorre todos los archivos de forma recursiva, indicando dónde se encontró el texto con contexto. Imagina pedirle a Claude: "Busca 'TODO' en todos los archivos de mi proyecto" — esta tool lo hace posible.

💎 Concepto principal

La tool buscar_em_arquivos(pasta: str, texto: str) usa Path(pasta).rglob("*") para iterar recursivamente sobre todos los archivos. Para cada archivo de texto, lee las líneas y verifica si aparece el texto buscado (sin distinguir entre mayúsculas y minúsculas con .lower()). El resultado incluye: nombre del archivo, número de línea e a línea con contexto (la línea encontrada, más una línea antes y otra después). Limita el número de resultados (p. ej., máximo 50) para no sobrecargar la respuesta.

💡 Consejo práctico

Usa rglob("*") para la búsqueda recursiva (incluye subcarpetas) y filtra solo archivos con path.is_file(). Ignora los archivos binarios comprobando la extensión o usando un try/except al leer. Una buena lista de extensiones de texto: .txt, .py, .js, .md, .html, .css, .json, .yml, .toml, .cfg, .ini, .log. Ignorar carpetas como .git, __pycache__ e node_modules acelera mucho la búsqueda.

📋 Flujo de búsqueda
Paso 1: Validar la carpeta

Comprobar que la ruta exista y sea un directorio con Path(pasta).is_dir(). Devolver un error claro si no lo es.

Paso 2: Iterar y buscar

Usar rglob("*") para recorrer archivos, leer cada uno con try/except y verificar si el texto aparece en cada línea.

Paso 3: Dar formato a los resultados

Armar una cadena con archivo:línea:contenido para cada coincidencia encontrada. Incluir el recuento total: "Se encontraron X coincidencias en Y archivos."

4

📊 Tool: estadísticas de la carpeta

La tool estatisticas_pasta analiza una carpeta y devuelve un panorama completo: cuántos archivos hay, cómo se distribuyen por extensión, cuál es el tamaño total, cuál es el archivo más grande y el más pequeño, y cuándo se modificó el archivo más reciente. Es como una "radiografía" del directorio.

💎 Concepto principal

La tool estatisticas_pasta(caminho: str) recorre todos los archivos de la carpeta con Path(caminho).rglob("*"), recopilando información con path.stat() para cada archivo. Calcula: total de archivos, distribución por extensión (usando un diccionario/Counter), tamaño total en bytes/KB/MB, archivo más grande y más pequeño con sus nombres y tamaños, y fecha del archivo más reciente. El resultado es una cadena formateada que Claude presenta como un informe organizado.

📊 Datos e investigación

Las herramientas de análisis de directorios son sorprendentemente útiles en el día a día. Los estudios muestran que el usuario promedio tiene más de 100.000 archivos en la computadora y tarda aproximadamente 2,5 horas por semana buscando y organizando archivos. Una tool que proporciona estadísticas rápidas permite identificar rápidamente las carpetas que necesitan limpieza, los archivos enormes que ocupan espacio y las extensiones inesperadas que pueden indicar problemas.

💡 Consejo práctico

Usa collections.Counter para contar extensiones de forma elegante: Counter(p.suffix.lower() for p in pasta.rglob("*") if p.is_file()). Para mostrar los tamaños en un formato legible, crea una función auxiliar que convierta bytes a KB/MB/GB automáticamente. Ordena las extensiones por cantidad (las más comunes primero) para que el informe muestre la información más relevante al inicio.

5

📂 Tool: organizar por tipo

La tool de mayor impacto de nuestro asistente: organizar_por_tipo analiza una carpeta y mueve cada archivo a una subcarpeta correspondiente a su extensión. Los archivos .pdf van a una carpeta "PDFs/", .jpg y .png a "Imagens/", .py a "Python/", y así sucesivamente. Pero atención: esta tool modifica el sistema de archivos, así que debe pedir confirmación antes de actuar.

💎 Concepto principal

La tool organizar_por_tipo(pasta: str, confirmar: bool = False) funciona en dos modos. Cuando confirmar=False (predeterminado), solo enumera los cambios planificados: "Mover relatorio.pdf a PDFs/relatorio.pdf", "Mover foto.jpg a Imagens/foto.jpg", etc. Cuando confirmar=True, realiza los cambios usando shutil.move(). El mapeo de extensiones a carpetas usa un diccionario: {".pdf": "PDFs", ".jpg": "Imagens", ".png": "Imagens", ".py": "Python", ...}. Las extensiones desconocidas van a "Otros/".

❌ Evitar
  • •Mover archivos sin mostrar primero el plan
  • •Sobrescribir archivos con nombres duplicados
  • •Organizar carpetas del sistema u ocultas
  • •Mover archivos de forma recursiva en subcarpetas
✅ Hacer
  • •Siempre enumera los cambios antes de ejecutar
  • •Renombrar si ya existe un archivo con el mismo nombre
  • •Ignorar los archivos ocultos (empiezan con ".")
  • •Organizar solo el nivel raíz de la carpeta de destino
🚨 Alerta — ¡Siempre confirma antes de mover!

Nunca muevas archivos automáticamente sin la confirmación del usuario. El patrón de la tool debe ser confirmar=False, devolviendo solo la lista de cambios planificados. Claude le presentará esa lista al usuario y le preguntará si desea continuar. Solo cuando el usuario confirme, Claude volverá a llamar a la tool con confirmar=True. Este enfoque en dos pasos evita los movimientos accidentales de archivos importantes.

6

🧪 Probando con Claude

Con todas las tools implementadas, probaremos el Asistente de Archivos en escenarios reales. El objetivo es validar que Claude pueda entender solicitudes en lenguaje natural, elegir la tool correcta y presentar los resultados de forma útil. Cada escenario prueba una combinación distinta de tools y capacidades.

💎 Concepto principal

Configura el servidor en Claude Desktop y crea una carpeta de prueba con archivos variados (textos, PDFs, imágenes, código Python). Cuanto más diversa sea la carpeta de prueba, más escenarios podrás validar. Observa cómo Claude decide qué tool usar; a veces combina varias en secuencia, por ejemplo, primero llama a estatisticas_pasta para saber qué hay en la carpeta y luego a ler_arquivo para inspeccionar un archivo específico.

📋 Escenarios de prueba sugeridos
Prueba 1: Explorar

"¿Qué hay en mi carpeta Downloads?" — Claude debe llamar a estatisticas_pasta y presentar un resumen organizado con el conteo por tipo, el tamaño total, etc.

Prueba 2: Buscar

"Busca 'TODO' en todos los archivos de mi proyecto" — Claude debe llamar a buscar_em_arquivos y enumerar cada coincidencia con archivo, línea y contexto.

Prueba 3: Leer

"Lee el archivo notas.txt y hazme un resumen" — Claude debe llamar a ler_arquivo y luego resumir el contenido naturalmente en la respuesta.

Prueba 4: Organizar

"Organiza los archivos de la carpeta Teste por tipo" — Claude primero debe mostrar el plan (confirmar=False), preguntar y solo después ejecutar (confirmar=True).

💡 Consejo práctico

Crea una carpeta de pruebas dedicada con archivos de ejemplo antes de probar: nunca pruebes directamente en carpetas importantes. Usa mkdir pasta_teste && touch pasta_teste/doc.pdf pasta_teste/foto.jpg pasta_teste/notas.txt pasta_teste/script.py para crear rápidamente una estructura de prueba. Esto permite probar todas las tools sin riesgo de afectar archivos reales, especialmente la tool de organización que mueve archivos.

📝 Resumen del módulo

  • ✓ Planificamos 4 tools para el Asistente de Archivos: leer, buscar, estadísticas y organizar.
  • ✓ Implementamos ler_arquivo con metadatos y límite de tamaño; Claude resume el contenido de forma natural.
  • ✓ Creamos buscar_em_arquivos con búsqueda recursiva mediante rglob, que devuelve el archivo, la línea y el contexto.
  • ✓ Implementamos estadisticas_pasta con conteo por extensión, tamaño total e identificación de extremos.
  • ✓ Construimos organizar_por_tipo con confirmación en dos pasos: primero lista y después ejecuta.
  • ✓ Probamos el asistente completo con escenarios reales de exploración, búsqueda, lectura y organización.
