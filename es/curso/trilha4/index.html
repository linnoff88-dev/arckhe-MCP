📋 Administrador de tareas

MCP Server que crea, lista, actualiza y elimina tareas guardadas en un archivo JSON.

Qué es:

La planificación del proyecto implica definir qué funcionalidades tendrá el gestor de tareas, cómo se almacenarán los datos y qué tools se expondrán mediante MCP. Es el momento de pensar antes de programar.

Por qué aprender:

Planificar antes de implementar evita tener que rehacer el trabajo y garantiza que construyas un server coherente. Esta disciplina es esencial en cualquier proyecto profesional.

Conceptos clave:

Levantamiento de requisitos, definición del alcance, diseño de tools, arquitectura de datos, MVP.

Qué es:

La estructura de datos define cómo se representará cada tarea en JSON, con campos como id, título, descripción, estado, fecha de creación y prioridad. El archivo JSON sirve como una base de datos sencilla y portátil.

Por qué aprender:

Modelar los datos correctamente es la base de cualquier aplicación. Un schema bien definido facilita la implementación de las tools y evita errores de inconsistencia.

Conceptos clave:

Schema JSON, modelado de datos, campos obligatorios vs. opcionales, tipos de datos, persistencia en archivos.

Qué es:

La tool de creación recibe el título, la descripción y la prioridad como parámetros, genera un ID único, registra la fecha de creación y guarda la nueva tarea en el archivo JSON. Es la primera operación CRUD del servidor.

Por qué aprender:

Crear es la operación más fundamental. Implementarla como tool de MCP te enseña el flujo completo: recibir parámetros, validarlos, procesarlos y devolver el resultado.

Conceptos clave:

CRUD, generación de ID, validación de entrada, escritura en archivo, respuesta estructurada, inputSchema.

Qué es:

La tool de listado lee el archivo JSON y devuelve las tareas, con opciones de filtro por estado (pendiente, en curso, completada) y prioridad. Permite que Claude presente las tareas al usuario de forma organizada.

Por qué aprender:

El listado con filtros es una operación esencial en cualquier sistema. Aprendes a implementar parámetros opcionales y formato de salida para el modelo.

Conceptos clave:

Lectura de archivos, filtrado de datos, parámetros opcionales, formato de salida, paginación.

Qué es:

Las tools de actualización y eliminación completan el CRUD. La actualización permite cambiar el estado, el título o la prioridad de una tarea existente. La eliminación borra una tarea por su ID. Ambas incluyen una validación para garantizar que la tarea exista.

Por qué aprender:

Las operaciones de escritura requieren especial cuidado: validar la existencia, gestionar errores y garantizar la atomicidad. Estas prácticas son fundamentales en cualquier proyecto real.

Conceptos clave:

Update, delete, validación de ID, manejo de errores, atomicidad, feedback al modelo.

Qué es:

Prueba end-to-end del administrador de tareas: configurar en Claude Desktop, crear tareas mediante una conversación natural, listar con filtros, actualizar el estado y eliminar tareas. Verificar que el archivo JSON persista correctamente entre sesiones.

Por qué aprender:

Probar el flujo completo revela errores que las pruebas unitarias no detectan. Es el momento de validar que todo funcione como un sistema integrado.

Conceptos clave:

Prueba end-to-end, escenarios de uso, edge cases, persistencia, debugging de servidor MCP.

🗄️ Consultor de bases de datos

MCP Server que se conecta a SQLite y permite consultas en lenguaje natural.

Qué es:

SQLite es una base de datos relacional integrada que no necesita un servidor aparte. Con Python, usamos el módulo nativo sqlite3 para crear, consultar y manipular datos. Es perfecta para proyectos MCP por su sencillez y portabilidad.

Por qué aprender:

SQLite es la base de datos más usada del mundo. Dominarla con Python te da las bases para conectar cualquier base de datos a un MCP Server.

Conceptos clave:

SQLite, módulo sqlite3, conexión, cursor, base de datos integrada, cero configuración.

Qué es:

Creación de una base de datos de ejemplo con tablas como clientes, productos y pedidos, cargada con datos realistas. Esta base de datos servirá como base para las consultas del MCP Server y simulará un escenario empresarial real.

Por qué aprender:

Contar con datos realistas para probar es fundamental. Aprendes a crear esquemas relacionales y a llenar tablas, habilidades esenciales para cualquier desarrollador.

Conceptos clave:

CREATE TABLE, INSERT, tipos de datos SQL, claves primarias, claves foráneas y datos seed.

Qué es:

La tool de consulta recibe una query SQL o una descripción en lenguaje natural, ejecuta el SELECT en la base de datos y devuelve los resultados con formato. Claude traduce las preguntas en lenguaje natural a SQL y presenta los resultados de forma legible.

Por qué aprender:

Las consultas en lenguaje natural sobre bases de datos son uno de los casos de uso más poderosos de MCP. Transformas datos sin procesar en información accesible para cualquier persona.

Conceptos clave:

SELECT, formato de resultados, traducción de lenguaje natural a SQL, límite de filas, metadatos de columnas.

Qué es:

Las tools para INSERT y UPDATE permiten que Claude agregue nuevos registros y actualice datos existentes en la base de datos. Incluye validación de campos, confirmación antes de ejecutar y comentarios sobre las filas afectadas.

Por qué aprender:

Las operaciones de escritura son más delicadas que las de lectura. Aprenderás a implementar confirmaciones, rollback y feedback, patrones esenciales para los servers que modifican datos.

Conceptos clave:

INSERT, UPDATE, validación, confirmación, filas afectadas, commit, rollback.

Qué es:

SQL injection es un ataque en el que se inserta código malicioso en consultas SQL. Para protegerte, usa consultas parametrizadas, sanitiza las entradas, limita los permisos de la base de datos y restringe las operaciones que puede ejecutar el MCP Server.

Por qué aprender:

La seguridad no es opcional. Un MCP Server que accede a una base de datos sin protección contra injection es una vulnerabilidad grave. Este conocimiento protege tus datos y a tus usuarios.

Conceptos clave:

SQL injection, consultas parametrizadas, sanitización, principio de mínimo privilegio, lista de permitidos de operaciones.

Qué es:

Prueba práctica en la que le haces preguntas a Claude como «¿cuáles fueron los pedidos del mes pasado?» o «¿qué cliente compró más?» y él las traduce a SQL, las ejecuta mediante MCP Server y presenta los resultados de forma clara.

Por qué aprender:

Ver el flujo completo en acción —desde la pregunta en lenguaje natural hasta el resultado formateado— consolida todo lo aprendido y muestra el verdadero potencial de un MCP Server de base de datos.

Conceptos clave:

Lenguaje natural para SQL, pruebas interactivas, escenarios complejos, joins, agregaciones, presentación de datos.

📁 Asistente de archivos

MCP Server que lee, resume y organiza archivos de una carpeta local.

Qué es:

La planificación define qué operaciones con archivos ofrecerá el MCP Server: lectura, resumen, búsqueda de contenido, estadísticas y organización automática. Cada funcionalidad se convierte en una tool con parámetros y valores de retorno bien definidos.

Por qué aprender:

Planificar las tools antes de implementarlas garantiza la coherencia y evita la superposición de funcionalidades. Un buen diseño de API es la base de un server fácil de usar.

Conceptos clave:

Diseño de API, operaciones con archivos, alcance de permisos, separación de responsabilidades, convenciones de nomenclatura.

Qué es:

La tool de lectura abre un archivo por su ruta y devuelve su contenido a Claude, que luego puede resumirlo, explicarlo o responder preguntas al respecto. Admite distintos formatos, como texto, markdown, código y CSV.

Por qué aprender:

Leer e interpretar archivos es uno de los usos más prácticos de MCP. Transformas Claude en un asistente que entiende tus documentos locales.

Conceptos clave:

Lectura de archivos, detección de codificación, límite de tamaño, formatos compatibles, manejo de errores de IO.

Qué es:

La tool de búsqueda recorre archivos de una carpeta buscando un término o patrón. Devuelve los archivos que contienen el término, con fragmentos de contexto alrededor de cada coincidencia, similar a un grep inteligente.

Por qué aprender:

La búsqueda en archivos es muy útil para encontrar información en proyectos, documentación o notas. Claude se convierte en un asistente de investigación para tus archivos locales.

Conceptos clave:

Búsqueda recursiva, regex, contexto de coincidencias, filtro por extensión y rendimiento en directorios grandes.

Qué es:

La tool de estadísticas analiza una carpeta y devuelve métricas como el número total de archivos, el tamaño total, la distribución por tipo de archivo, los archivos más grandes, los más recientes y la estructura de subdirectorios.

Por qué aprender:

Tener una vista general rápida de una carpeta es útil para entender proyectos, identificar problemas de organización y encontrar archivos que requieren atención.

Conceptos clave:

Análisis de directorios, métricas de archivos, agrupación por extensión, tamaño formateado, árbol de directorios.

Qué es:

La tool de organización mueve archivos a subcarpetas según su tipo: imágenes a /imagens, documentos a /documentos, código a /codigo. Incluye una vista previa antes de ejecutarse y una opción para deshacer.

Por qué aprender:

La automatización de la organización es un caso de uso potente y práctico. Aprenderás a implementar operaciones destructivas de forma segura: vista previa, confirmación y rollback.

Conceptos clave:

Movimiento de archivos, categorización por extensión, vista previa de operaciones, dry-run, rollback.

Qué es:

Prueba práctica del asistente de archivos: pedirle a Claude que resuma un documento, busque información en múltiples archivos, muestre estadísticas de un proyecto y organice una carpeta desordenada. Validación completa de todas las tools.

Por qué aprender:

Probar con escenarios reales garantiza que el server funciona en condiciones prácticas. Descubres casos límite y mejoras la experiencia del usuario.

Conceptos clave:

Prueba funcional, escenarios de uso real, edge cases de archivos, permisos, encoding, archivos grandes.

🌐 Integración con API REST

MCP Server que consume la API de GitHub y expone acciones como tools.

Qué es:

La API REST de GitHub permite acceder a repositorios, issues, pull requests y más mediante HTTP. Entender sus endpoints, el formato de respuesta JSON, la paginación y los rate limits es esencial para crear un MCP Server que la consuma.

Por qué aprender:

La API de GitHub es una de las API REST mejor documentadas del mundo. Aprender a consumirla mediante MCP te prepara para integrar cualquier API REST con el protocolo.

Conceptos clave:

API REST, endpoints, métodos HTTP, JSON, paginación, limitación de solicitudes, documentación de API.

Qué es:

La autenticación con la API de GitHub usa Personal Access Tokens (PAT). Aprenderás a crear tokens con los permisos mínimos, almacenarlos de forma segura mediante variables de entorno y usarlos en el MCP Server sin exponerlos en el código.

Por qué aprender:

Gestionar las credenciales de forma segura es fundamental en cualquier integración. Los patrones que aprenderás aquí se aplican a cualquier API que requiera autenticación.

Conceptos clave:

Personal Access Token, alcances, variables de entorno, .env, seguridad de credenciales, Bearer token.

Qué es:

La tool de listado de repositorios consulta la API de GitHub y devuelve los repos del usuario autenticado, con información como nombre, descripción, lenguaje, estrellas y fecha de actualización. Admite filtros por visibilidad y ordenamiento.

Por qué aprender:

Es la primera tool que consume una API externa real. Aprendes el patrón completo: hacer una solicitud HTTP, procesar la respuesta, formatearla para el modelo y manejar errores de red.

Conceptos clave:

Solicitud GET, parsing de JSON, formato de datos, filtros, ordenación, manejo de errores HTTP.

Qué es:

La tool de búsqueda de issues permite consultar issues de un repositorio específico, filtrando por estado (open, closed), labels y términos de búsqueda. Devuelve el título, la descripción, el autor, las labels y los comentarios de cada issue.

Por qué aprender:

Las issues son el corazón de la gestión de proyectos en GitHub. Con esta tool, Claude puede ayudar a analizar, priorizar y responder issues de forma inteligente.

Conceptos clave:

API de issues, filtros de estado, labels, búsqueda de texto, paginación de resultados, datos anidados.

Qué es:

La tool de creación de issues envía un POST a la API de GitHub con título, cuerpo, labels y assignees. Claude puede crear issues bien formateadas a partir de descripciones del usuario en lenguaje natural.

Por qué aprender:

Crear recursos mediante la API es una operación de escritura que requiere cuidado. Aprenderás a implementar una confirmación antes de ejecutar y a dar formato a los datos para enviarlos mediante POST.

Conceptos clave:

Solicitud POST, cuerpo de la solicitud, validación de entrada, confirmación de acción, respuesta de creación, estado 201.

Qué es:

Prueba end-to-end de la integración con GitHub: listar repos, buscar issues de un proyecto, crear una nueva issue y verificar que aparezca en GitHub. Incluye pruebas de error, como un token inválido y un repositorio inexistente.

Por qué aprender:

Probar integraciones con APIs externas exige considerar escenarios que no existen en proyectos locales: latencia, errores de red, límites de solicitudes y respuestas inesperadas.

Conceptos clave:

Prueba de integración, mocking, escenarios de error, timeout, retry, rate limiting, validación de datos.

🔗 Combinando múltiples servidores

Configura Claude Desktop con 2+ servers simultáneos para crear un asistente potente.

Qué es:

La arquitectura MCP permite que un Host conecte varios Servers al mismo tiempo. Cada server está especializado en una tarea y Claude los coordina automáticamente, creando un asistente que combina diversas capacidades.

Por qué aprender:

Combinar servers es lo que hace que MCP sea realmente potente. En lugar de un server monolítico, compones capacidades modulares que pueden reutilizarse en distintos contextos.

Conceptos clave:

Composición de servers, modularidad, especialización, orquestación por el modelo, reutilización.

Qué es:

Configurar varios servers en Claude Desktop implica agregar varias entradas en el archivo claude_desktop_config.json, cada una con su comando, argumentos y variables de entorno. Claude se conecta a todos al mismo tiempo al iniciarse.

Por qué aprender:

Saber configurar varios servers es la habilidad práctica que transforma Claude Desktop en un asistente personalizado con todas tus herramientas favoritas.

Conceptos clave:

claude_desktop_config.json, múltiples entradas, variables de entorno por server, inicio simultáneo, naming.

Qué es:

Cuando hay varios servers conectados, Claude recibe la lista completa de tools disponibles y elige automáticamente cuál usar según la intención del usuario. El nombre y la descripción de cada tool son fundamentales para este enrutamiento inteligente.

Por qué aprender:

Entender cómo Claude enruta entre servers te ayuda a crear tools con nombres y descripciones que facilitan la elección correcta y evitan ambigüedades y conflictos.

Conceptos clave:

Enrutamiento de tools, nombres descriptivos, resolución de ambigüedades, tool discovery, contexto de decisión.

Qué es:

Ejemplo práctico que combina el gestor de tareas (Módulo 4.1) con el consultor de bases de datos (Módulo 4.2). Claude puede crear tareas basadas en datos de la base de datos o consultar la base para priorizar tareas existentes.

Por qué aprender:

Este ejemplo concreto muestra cómo se complementan dos servers independientes. Es la prueba práctica de que la modularidad funciona y genera capacidades emergentes.

Conceptos clave:

Composición práctica, flujo multi-server, capacidades emergentes, escenario de negocio, datos cruzados.

Qué es:

Ejemplo práctico que combina el asistente de archivos (Módulo 4.3) con la integración de GitHub (Módulo 4.4). Claude puede leer código local, analizar bugs y crear issues en GitHub automáticamente con contexto relevante.

Por qué aprender:

Este escenario simula un flujo de trabajo de desarrollo real. Combinar la lectura de código local con la gestión de issues crea un asistente de desarrollo verdaderamente útil.

Conceptos clave:

Flujo de trabajo de desarrollo, análisis de código, creación automática de issues, contexto cruzado, automatización.

Qué es:

Prueba completa del asistente multiservidor: conversar con Claude usando 3-4 servers simultáneos, verificar que elija el server correcto para cada tarea, probar escenarios que involucren múltiples servers en secuencia y evaluar la experiencia general.

Por qué aprender:

La prueba multi-server revela problemas de naming, conflictos entre tools y límites de contexto. Es la prueba definitiva de tu arquitectura MCP.

Conceptos clave:

Prueba multiservidor, conflictos de nombres, límite de contexto, rendimiento, experiencia del usuario, debugging.

🛡️ Buenas prácticas de seguridad

Control de permisos, autenticación, principio de mínimo privilegio y riesgos comunes.

Qué es:

Los MCP Servers tienen acceso a recursos reales: archivos, bases de datos, APIs y sistemas. Un server inseguro puede exponer datos sensibles, ejecutar acciones destructivas o ser vulnerable a prompt injection. La seguridad no es un extra, es una necesidad.

Por qué aprender:

Entender los riesgos reales motiva la implementación de prácticas de seguridad. Sin esa conciencia, los desarrolladores crean servers que funcionan, pero son peligrosos en producción.

Conceptos clave:

Superficie de ataque, prompt injection, exposición de datos, acciones destructivas, responsabilidad del desarrollador.

Qué es:

El principio de mínimo privilegio establece que un server solo debe tener acceso a los recursos estrictamente necesarios para su función. Un server que lee archivos no necesita permiso de escritura. Un server que consulta SQL no necesita permiso de DELETE.

Por qué aprender:

Este principio es la defensa más eficaz contra errores y ataques. Limitar los permisos reduce drásticamente el impacto de cualquier falla de seguridad.

Conceptos clave:

Mínimo privilegio, permisos granulares, alcance mínimo, sandboxing, aislamiento de recursos.

Qué es:

La gestión segura de credenciales implica no incluir nunca tokens directamente en el código, usar variables de entorno o gestores de secretos, rotar los tokens periódicamente y usar los permisos mínimos. Cada server debe tener sus propias credenciales aisladas.

Por qué aprender:

La filtración de credenciales es una de las vulnerabilidades más comunes y graves. Las buenas prácticas de gestión de tokens protegen tus servicios y a tus usuarios.

Conceptos clave:

Variables de entorno, gestores de secretos, rotación de tokens, alcances mínimos, .gitignore, credenciales por entorno.

Qué es:

Entre los riesgos comunes están exponer todo el sistema de archivos, permitir la ejecución arbitraria de comandos, no validar las entradas, confiar ciegamente en lo que envía el modelo, no limitar la tasa de solicitudes y no registrar las operaciones sensibles.

Por qué aprender:

Conocer los riesgos más frecuentes te permite evitarlos de forma proactiva. Es mucho más fácil prevenir una vulnerabilidad que corregirla después de un incidente.

Conceptos clave:

Path traversal, inyección de comandos, validación de entradas, rate limiting, logging, confianza cero.

Qué es:

Una lista práctica para revisar antes de publicar cualquier MCP Server: validación de entradas, permisos mínimos, credenciales seguras, limitación de solicitudes, registro de eventos, manejo de errores sin exponer datos, documentación de seguridad y pruebas de abuso.

Por qué aprender:

Tener una lista de verificación elimina el riesgo de olvidar aspectos de seguridad por las prisas de publicar. Es una herramienta práctica que usarás en cada proyecto MCP.

Conceptos clave:

Lista de verificación de seguridad, revisión antes de publicar, validación, permisos, logging, documentación, pruebas de abuso.

Qué es:

La auditoría y el monitoreo consisten en registrar todas las operaciones del server (quién las solicitó, qué se hizo y cuándo), monitorear el uso anómalo, alertar sobre intentos sospechosos y conservar registros para investigar. Así puedes ver lo que está haciendo tu server.

Por qué aprender:

Sin monitoreo, no sabes si tu server se está usando de forma maliciosa. Los logs y las alertas marcan la diferencia entre descubrir un problema en minutos o en meses.

Conceptos clave:

Logging estructurado, audit trail, monitoreo, alertas, métricas, detección de anomalías, retención de logs.
