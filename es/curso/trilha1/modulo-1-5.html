🧰 Herramientas: acciones que el modelo puede ejecutar

Las tools son el tipo de recurso más poderoso y más utilizado en el ecosistema MCP. Representan acciones concretas que el modelo de IA puede ejecutar — funciones con parámetros bien definidos que permiten consultar APIs, ejecutar scripts, enviar mensajes, procesar datos e interactuar con sistemas externos. El modelo analiza el contexto de la conversación, decide cuándo se necesita una tool, selecciona la más adecuada y define los parámetros correctos para la llamada.

💎 Concepto principal

Una Tool en MCP es una función ejecutable que el servidor expone al modelo de IA. Cada tool tiene un nombre, una descripción y un esquema de parámetros (JSON Schema) que define exactamente qué datos espera recibir. El modelo decide cuándo y cómo llamarlas según el contexto de la conversación, sin que sea obligatoria la intervención humana.

read_file
Lee el contenido de un archivo en el sistema de archivos local o remoto.
query_database
Ejecuta una consulta SQL en una base de datos conectada.
send_email
Envía un correo electrónico con destinatario, asunto y cuerpo definidos.
📊 Datos e investigación

Las tools son, por mucho, el tipo de recurso más utilizado en el ecosistema MCP. Se estima que cerca del 80 % de los servidores MCP publicados exponen al menos una tool; muchos exponen exclusivamente tools. Esto refleja el caso de uso más común: permitir que el modelo de IA ejecuta acciones en el mundo real, desde consultas sencillas hasta operaciones complejas en varios sistemas.

2

📦 Resources — Datos a los que puede acceder el modelo

Los Resources representan datos y contenidos que el servidor MCP pone a disposición del modelo para que las consulte. A diferencia de las tools, los resources no ejecutan acciones: funcionan como archivos virtuales que el modelo puede leer cuando necesita información. Documentos, registros de bases de datos, configuraciones del sistema, logs, esquemas: todo puede exponerse como resource. Cada resource se identifica mediante un URI único que sigue un esquema estandarizado.

💎 Concepto principal

Una Resource en MCP es un dato o contenido que el servidor expone para su lectura. Cada resource tiene un URI (Uniform Resource Identifier) que la identifica de forma única; por ejemplo, file:///config/settings.json o db://users/schema. El modelo lee el resource cuando necesita contexto adicional, pero no ejecuta acciones a través de ella. Los Resources son pasivos: informan, no transforman.

💡 Consejo práctico

Piensa en Resources como una biblioteca — el modelo va hasta el estante, consulta el libro que necesita, asimila la información y vuelve a la conversación con más contexto. No modifica los libros, no reorganiza el estante ni escribe páginas nuevas. Solo lee y consulta. Si necesitas que el modelo haga algo con los datos (modificarlos, enviarlos, procesarlos), esa tarea corresponde a una Tool, no a un Resource.

3

📝 Prompts — plantillas reutilizables de instrucciones

Los prompts son el tercer tipo de recurso en MCP, y el más sutil. Permiten que el servidor proporcione plantillas reutilizables de instrucciones estructuradas que guían el comportamiento del modelo en tareas específicas. En lugar de que el usuario escriba manualmente "analiza este código y encuentra bugs", el servidor puede ofrecer un prompt predefinido como code_review que ya contiene todas las instrucciones necesarias. El usuario o el modelo puede invocar estos prompts.

💎 Concepto principal

Un Prompt en MCP es una plantilla de instrucciones que el servidor expone para que el usuario o el modelo la invoque. Cada prompt tiene un nombre, una descripción y puede aceptar parámetros (argumentos) que personalizan las instrucciones. Ejemplos: "analiza este código" (con parámetro de idioma), "genera un informe de ventas" (con parámetro de período), "resume este documento" (con parámetro de formato). Los prompts encapsulan experiencia y buenas prácticas en instrucciones reutilizables.

✅ Prompts bien construidos
  • •Específicos: "Revisa este código Python para detectar vulnerabilidades de seguridad"
  • •Con parámetros claros: lenguaje, formato de salida, nivel de detalle
  • •Bien descritos: el nombre y la descripción explican exactamente qué hacen
  • •Consistentes: formato de salida predecible y estructurado
❌ Prompts que debes evitar
  • •Genéricos: "Haz algo con este código"
  • •Sin parámetros: instrucciones fijas que no se adaptan al contexto
  • •Vagos: el nombre y la descripción no explican el propósito
  • •Redundantes: duplican funcionalidades que ya están disponibles en las tools

🔀 Diferencias entre los tres

La clave para dominar MCP es entender claramente la distinción entre los tres tipos de recursos. Las tools son acciones (verbos) — hacen cosas. Los Resources son datos (sustantivos) — informan. Los Prompts son instrucciones (plantillas) — guían. Las Tools pueden alterar el estado del mundo real, los Resources son estrictamente de solo lectura y los Prompts moldean el comportamiento del modelo sin ejecutar ni leer directamente.

💎 Concepto principal
Aspecto Tools Resources Prompts
Naturaleza Acciones (verbos) Datos (sustantivos) Instrucciones (plantillas)
Función Ejecutar operaciones Proporcionar información Guiar el comportamiento
¿Cambia el estado? Sí No (lectura) No (orientación)
¿Quién invoca? El modelo decide El modelo consulta Usuario o modelo
Ejemplo send_email() file:///readme.md code_review
💡 Consejo práctico

Piénsalo así: Las tools hacen, los Resources informan, los Prompts guían. Cuando quieres que el modelo haz algo (enviar, crear, eliminar, procesar), usa una Tool. Cuando quieres que sepa algo (leer datos, consultar configuraciones, acceder a documentos), usa una Resource. Cuando quieres que sigue un patrón (analizar código de cierta manera, generar un informe en un formato específico), usa un Prompt.

5

🎯 Ejemplos en el mundo real

La mejor forma de entender la distinción entre Tools, Resources y Prompts es ver cómo se manifiestan en servidores MCP reales. Cada servidor combina los tres tipos según su dominio: un server de GitHub usa tools diferentes a las de un server de base de datos, pero ambos siguen la misma lógica de separación entre acciones, datos e instrucciones.

💎 Concepto principal

Mira cómo se aplican los tres tipos de recursos en servidores MCP del mundo real:

🐙 Servidor GitHub
Tools: crear issue, hacer merge de PR, crear branch
Resources: contenido de archivos, lista de repos
Prompts: revisar código, analizar PR
🗄️ Server Database
Tools: INSERT, UPDATE, DELETE
Resources: esquema de tablas, registros
Prompts: generar informe, optimizar query
📋 Servidores MCP y sus recursos
Server de archivos

Tools para crear, mover y eliminar archivos. Resources para leer contenido y listar directorios. Prompts para organizar proyectos y analizar la estructura de las carpetas.

Server de correo electrónico

Tools para enviar y responder correos electrónicos. Resources para acceder a la bandeja de entrada y los contactos. Prompts para redactar mensajes profesionales y resumir conversaciones.

Server de monitoreo

Tools para crear alertas y escalar incidentes. Resources para acceder a métricas y registros en tiempo real. Prompts para diagnosticar problemas y generar informes post mortem.

6

🧩 Combinando recursos

Un servidor MCP verdaderamente potente no se limita a un solo tipo de recurso: combina Tools, Resources y Prompts de forma inteligente para crear una experiencia completa. La sinergia entre los tres tipos es lo que transforma un servidor simple en una integración robusta y versátil, capaz de atender escenarios complejos del mundo real.

💎 Concepto principal

Imagina un servidor MCP de comercio electrónico completo:

🧰 Herramientas: procesar pedido, actualizar inventario, aplicar cupón de descuento, generar factura, calcular envío.
📦 Resources: catálogo de productos, historial de pedidos del cliente, tabla de precios, política de devoluciones, preguntas frecuentes.
📝 Prompts: atención al cliente, recomendación de productos, análisis de carritos abandonados, respuesta a reclamos.

Los tres tipos trabajan juntos: el Prompt de atención guía el modelo, las Resources informan sobre productos y pedidos, y las Tools ejecutan acciones como procesar devoluciones o aplicar descuentos.

💡 Consejo práctico

Al diseñar tu servidor MCP, comienza por identificar los tres pilares: qué acciones debe ejecutar el modelo (Tools), qué datos debe consultar (Resources) y qué patrones de comportamiento deben poder reutilizarse (Prompts). No todos los servidores necesitan los tres: muchos funcionan perfectamente solo con Tools, pero los más completos y útiles combinan los tres tipos de forma coherente.

📊 Datos e investigación

En la práctica, la distribución del uso de los tipos de recursos en el ecosistema MCP sigue un patrón claro: ~80% de los servers exponen Tools, ~40% exponen Resources, e ~20% exponen Prompts. Los servidores que combinan los tres tipos suelen ser los más completos y mejor valorados por la comunidad: ofrecen una experiencia integrada en la que el modelo puede actuar, consultar y seguir patrones, todo dentro del mismo servidor.

📝 Resumen del módulo

  • ✓ Las tools son acciones ejecutables (verbos): funciones con parámetros que el modelo invoca para interactuar con sistemas externos.
  • ✓ Los Resources son datos accesibles (sustantivos): contenidos identificados por URI que el modelo consulta para obtener información.
  • ✓ Los prompts son plantillas reutilizables (instrucciones): patrones estructurados que guían el comportamiento del modelo en tareas específicas.
  • ✓ Las tools modifican el estado, los Resources son de lectura y los Prompts orientan: cada tipo tiene una función distinta y complementaria.
  • ✓ Los servidores reales, como GitHub y Database, combinan los tres tipos para crear integraciones completas.
  • ✓ Los mejores servidores MCP combinan Tools, Resources y Prompts de forma coherente para ofrecer una experiencia integrada.
