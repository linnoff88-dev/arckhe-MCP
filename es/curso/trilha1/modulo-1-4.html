💻 Instalando Claude Desktop

El primer paso para ver MCP en funcionamiento es instalar Claude Desktop — la aplicación oficial de Anthropic que funciona como Host MCP. A diferencia de Claude en la web, Desktop admite la conexión directa con MCP Servers locales, lo que permite que el modelo acceda a herramientas en tu computadora. La descarga está disponible en claude.ai/download, con versiones para Windows, Mac y Linux.

💎 Concepto principal

O Claude Desktop es la aplicación nativa de Anthropic que funciona como un Host MCP. No es solo una interfaz para conversar con Claude: es el entorno que gestiona la conexión entre el modelo de IA y los MCP Servers instalados en tu máquina. Al usar Claude Desktop, tienes acceso a un Client MCP integrado que se comunica con servidores locales, lo que permite que Claude interactúe con archivos, bases de datos, APIs y cualquier otra herramienta que tenga un MCP Server disponible.

💡 Consejo práctico

Accede claude.ai/download en tu navegador. Elige la versión correspondiente a tu sistema operativo (Windows, macOS o Linux). Descarga el instalador, ejecútalo y sigue las instrucciones en pantalla. Cuando abras Claude Desktop por primera vez, inicia sesión con tu cuenta de Anthropic. Listo: ya tienes un Host MCP funcional en tu computadora.

📋 Pasos de la instalación
Paso 1 — Descarga

Accede a claude.ai/download y descarga el instalador para tu sistema operativo (Windows, macOS o Linux).

Paso 2 — Instalar

Ejecuta el instalador y sigue las instrucciones predeterminadas de tu sistema. En macOS, arrástralo a la carpeta Applications. En Windows, sigue el asistente. En Linux, usa el paquete .deb o .rpm.

Paso 3 — Abrir e iniciar sesión

Abre Claude Desktop, inicia sesión con tu cuenta de Anthropic y verifica que la interfaz se cargue correctamente. Ya puedes configurar MCP Servers.

2

⚙️ El archivo de configuración

Para que Claude Desktop sepa qué MCP Servers están disponibles, debes registrarlos en un archivo de configuración llamado claude_desktop_config.json. Este archivo es el corazón de la integración: aquí declaras a qué servidores puede acceder Claude, cómo ejecutarlos y qué argumentos pasarles. Sin este archivo configurado correctamente, Claude Desktop no sabrá que hay herramientas MCP disponibles.

💎 Concepto principal

O claude_desktop_config.json es el archivo donde registras todos los MCP Servers que quieres poner a disposición de Claude Desktop. Se encuentra en un directorio específico del sistema: en el macOS, en ~/Library/Application Support/Claude/; en el Windows, en %APPDATA%/Claude/. La estructura principal es un objeto JSON con el campo "mcpServers", donde cada clave es el nombre del servidor y el valor contiene el comando de ejecución y sus argumentos.

💡 Consejo práctico

La estructura básica del archivo es sencilla. Mira el esqueleto:

{
  "mcpServers": {
    "nome-do-server": {
      "command": "comando-para-executar",
      "args": ["argumento1", "argumento2"]
    }
  }
}

Cada servidor es una entrada dentro de "mcpServers". El campo "command" define cómo ejecutar el servidor (por ejemplo: npx) e "args" son los argumentos que se pasan al comando.

🚨 Alerta

Ten cuidado al editar el JSON manualmente: las comas y las comillas importan! Un error común es olvidar una coma entre servidores o dejar una coma sobrante después del último elemento. Otro error frecuente es usar comillas simples en lugar de comillas dobles (JSON exige comillas dobles). Si Claude Desktop no reconoce tus servidores, lo primero que debes verificar es la sintaxis del JSON. Usa un validador en línea como jsonlint.com para comprobar que el archivo esté correcto antes de reiniciar la aplicación.

3

📁 Conectando el servidor filesystem

O @modelcontextprotocol/server-filesystem es uno de los MCP Servers oficiales más populares. Permite que Claude acceda a los archivos de tu computadora, los lea, cree y edite, pero solo en los directorios que autorices explícitamente. Es el servidor perfecto para empezar porque es fácil de configurar y demuestra claramente el poder de MCP: Claude empieza a «ver» tus archivos locales.

💎 Concepto principal

O Filesystem Server es un MCP Server que expone operaciones del sistema de archivos como tools MCP. Ofrece herramientas como read_file (leer el contenido de un archivo), write_file (crear o sobrescribir archivos), list_directory (listar los archivos de una carpeta) y otras. El servidor solo permite el acceso a los directorios especificados en los argumentos de configuración, lo que garantiza que Claude no acceda a datos fuera del alcance autorizado.

💡 Consejo práctico

Agrega esta configuración a tu claude_desktop_config.json:

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/seu-usuario/Documents"
      ]
    }
  }
}

Reemplaza /Users/seu-usuario/Documents por la ruta del directorio al que quieres que Claude acceda. Puedes especificar varios directorios agregando más rutas a la lista de args. Requisito previo: tener el Node.js instalado (npx viene con Node).

❌ Evitar
  • •Dar acceso al directorio raíz (/ o C:\)
  • •Incluir carpetas con datos confidenciales (.ssh, .env)
  • •Autorizar todo el directorio del usuario (~)
  • •Olvidar restringir el alcance del acceso
✅ Hacer
  • •Restringir el acceso a directorios de trabajo específicos
  • •Crear una carpeta dedicada a las pruebas con MCP
  • •Revisar qué carpetas están autorizadas
  • •Empezar con los permisos mínimos necesarios
4

🧪 Probando la conexión

Después de configurar el archivo JSON, es hora de probar si todo funciona. Claude Desktop debe estar reiniciado para leer las nuevas configuraciones. Cuando el servidor MCP se carga correctamente, aparece un ícono de herramientas (martillo) en la interfaz, lo que indica que hay tools disponibles. Si el ícono no aparece, hay un problema en la configuración que debes investigar.

💎 Concepto principal

Claude Desktop lee el archivo de configuración solo al inicio. Esto significa que, después de cualquier cambio en el claude_desktop_config.json, tienes que cerrar la aplicación por completo y volver a abrirla. Cuando los MCP Servers se cargan correctamente, Claude Desktop muestra un ícono de martillo en el área de entrada, lo que indica que hay herramientas externas disponibles. Al hacer clic en este ícono, puedes ver la lista completa de tools que ofrecen los servidores conectados.

📋 Pasos de verificación
Paso 1 — Reiniciar

Cierra completamente Claude Desktop (no solo lo minimices: finaliza el proceso) y vuelve a abrirlo.

Paso 2 — Verificar el ícono

Mira el área de entrada de mensajes. Debe aparecer un ícono de martillo (🔨), que indica que se cargaron los MCP Servers.

Paso 3 — Listar tools

Haz clic en el ícono del martillo para ver la lista de tools disponibles. Deberías ver herramientas como read_file, write_file, list_directory, etc.

🚨 Alerta

Problemas comunes y cómo resolverlos:

  • •El ícono no aparece: el JSON tiene un error de sintaxis. Valídalo en jsonlint.com.
  • •Error al cargar el servidor: es posible que Node.js no esté instalado. Verifica con node --version en la terminal.
  • •El servidor aparece, pero muestra un error: es posible que la ruta del directorio no exista. Confirma que el directorio especificado en args sea válido.
  • •La aplicación no se vuelve a cargar: verifica si realmente cerraste el proceso y no solo minimizaste la ventana.
5

🎯 Usando tools en la práctica

Con el Filesystem Server conectado, es hora de probar las tools en la práctica. Lo más interesante es que tú no hace falta decirle a Claude qué tool usar — basta con hacer preguntas en lenguaje natural y el modelo decide de forma autónoma cuándo y qué herramienta usar. Es la inteligencia del modelo combinada con las capacidades de las tools MCP.

💎 Concepto principal

Cuando Claude Desktop tiene MCP Servers conectados, el modelo recibe la descripción de todas las tools disponibles en tu contexto. A partir de ahí, el modelo analiza cada prompt del usuario y decide de forma autónoma si necesita alguna tool para responder. No tienes que usar comandos especiales ni una sintaxis específica: basta con escribir en lenguaje natural. Claude elige la tool adecuada, la ejecuta a través del Client MCP, recibe el resultado y formula la respuesta final.

💡 Consejo práctico

Prueba estos prompts para probar las tools del Filesystem Server:

  • 1."Liste os arquivos na pasta Documents" — usa list_directory
  • 2."Leia o conteúdo do arquivo notas.txt" — usa read_file
  • 3."Crie um arquivo teste-mcp.txt com a frase: MCP está funcionando!" — usa write_file
  • 4."Quantos arquivos .json existem na pasta do projeto?" — combina list_directory + razonamiento

Observa cómo Claude solicita tu permiso antes de ejecutar cada tool: un mecanismo de seguridad del protocolo.

📊 Datos e investigación

El modelo decide de forma autónoma cuándo usar tools — este es uno de los pilares de MCP. El proceso funciona así: Claude recibe la lista de tools disponibles con sus descripciones y parámetros. Cuando el usuario hace una pregunta, el modelo evalúa si alguna tool ayudaría a responder. Si es así, genera una tool call (llamada a una herramienta) con los parámetros adecuados. No hay reglas fijas: es el modelo el que decide gracias a su inteligencia. Esto es fundamentalmente distinto de los chatbots tradicionales, que dependen de comandos explícitos como "/buscar" o "/crear".

6

🔍 Qué pasó por debajo

Cuando le pediste a Claude que enumerara archivos y respondió con el contenido real de tu directorio, ocurrió una sofisticada secuencia de eventos entre bastidores. Entender este flujo es esencial para dominar MCP, porque es exactamente el mecanismo que vas a construir y personalizar en los próximos módulos.

💎 Concepto principal

Lo que parece mágico en la superficie sigue un flujo preciso y estandarizado por debajo. Cada interacción con una tool MCP pasa por 6 etapas bien definidas: el prompt del usuario llega al Host (Claude Desktop), el modelo identifica que necesita usar una tool, el Client MCP envía una solicitud al Server, el Server ejecuta la operación, el resultado vuelve por el mismo camino y Claude formula la respuesta final incorporando los datos obtenidos. Todo este flujo ocurre en segundos, de forma transparente para el usuario.

📋 El flujo real — paso a paso
1. Prompt del usuario

Escribes «Enumera los archivos de la carpeta Documents» en Claude Desktop. El prompt se envía al modelo junto con la lista de tools disponibles.

2. Claude identifica la necesidad

El modelo (Host) analiza el prompt y decide que necesita la tool "list_directory" para responder. Genera una tool call con el parámetro del directorio.

3. El cliente MCP envía una solicitud

El Client MCP integrado en Claude Desktop recibe la llamada a la tool y la convierte en una solicitud JSON-RPC, que envía al Filesystem Server.

4. El servidor ejecuta la operación

El Filesystem Server recibe la solicitud, valida que el directorio esté en la lista de permitidos, lista los archivos en el sistema operativo y recopila los resultados.

5. El resultado vuelve

El Server envía la respuesta (lista de archivos) al Client MCP, que se la pasa al modelo. Ahora, los datos reales de tu computadora están en el contexto de Claude.

6. Claude responde

El modelo procesa los datos recibidos, da formato a la respuesta en lenguaje natural y te la muestra, como si hubiera mirado la carpeta por sí mismo.

💡 Consejo práctico

Observa que, durante la ejecución, Claude Desktop muestra exactamente qué tool se está invocando y con qué parámetros, antes de pedirte permiso. Esta transparencia es intencional: el protocolo MCP se diseñó para que las personas siempre sepan qué está pasando y puedan aprobar o rechazar cada acción. Presta atención a estos detalles durante tus pruebas: revelan el flujo real del protocolo en acción.
